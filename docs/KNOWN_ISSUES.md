# 已知问题与限制

## 风扇无法完全停转

当前风扇模块为 `G / V / S` 三线接口。如果只接 `G + V` 就会满速转动，说明供电后模块默认开启，`S` 脚可能只负责调速或使能，未必能切断风扇供电。

影响：

- PWM 可以改变转速，但可能无法让风扇完全归零。
- 若需要可靠停转，应增加电源开关管、EN 控制或更换支持关断的风扇模块。
- 当前风扇使用 TIM4_CH4 / PD15，TIM4 同时服务 WS2812，频率并非专为普通风扇 PWM 设计。

## ESP32 初始化和 AT 指令超时

ESP32 使用 AT 指令连接 WiFi 和 OneNET MQTT。初始化过程中可能出现超时或 busy 状态，需要等待非阻塞初始化状态机重试。

影响：

- WiFi 信号、OneNET 服务、AT 固件版本和供电稳定性都会影响初始化成功率。
- `APP/esp32.c` 中仍保留阻塞式初始化接口，但当前调度中主要使用非阻塞初始化。
- 更换 OneNET 设备后必须同步产品 ID、设备名、token、属性名和数据类型。

## OneNET 属性名与类型

当前代码上传 `MQ2` 和 `PM25` 的 ADC 原始值，类型应按整数配置，范围建议 `0~4095`，步长 `1`。

需要注意：

- 代码中 RGB 红色属性名使用 `RGB1_RAD` / `RGB2_RAD`，如果云端模型使用 `RED`，需要统一修改。
- 云端数据类型和步长不一致时，上传可能失败或显示异常。

## 烟雾 DO 连接需按当前硬件确认

当前烟雾模拟量 AO 已按实际接线配置为 PA1 / ADC1_IN1，`APP/smoke.c` 中 `SMOKE_ADC_CHANNEL` 为 `ADC_CHANNEL_1`。代码还保留 PC2 作为烟雾 DO 低电平报警辅助输入。

影响：

- 如果硬件没有实际接烟雾 DO，应主要使用 PA1 ADC 原始值判断烟雾状态。
- PA2 当前是 USART2_TX，用于 ESP32 通信，不应再接烟雾 DO。
- 后续硬件修版可继续保留 PC2 作为 DO，或完全移除数字报警脚依赖。

## ASRPRO 需要单独烧录

`asrpro_code.cpp` 不参与 STM32 CMake 编译，需要在 ASRPRO / 天问 Block 环境中单独更新。

当前语音逻辑限制：

- 唤醒词后保留 30 秒命令等待窗口。
- 查询命令保留 30 秒窗口，避免查询结果被退出提示打断。
- 控制命令执行后不主动开启等待窗口，避免执行一次命令后马上播报退出提示。
- 人脸和报警的外部 `PLAY/PLAYS` 不主动打开唤醒窗口。

如果烧录后仍出现无人唤醒时播报退出提示，需要检查 ASRPRO 是否误唤醒，或是否存在旧代码未覆盖。

## OpenART 人脸识别限制

`openart.py` 当前只识别 `zeng` 一个对象。

限制：

- 没有多用户身份管理。
- 没有陌生人告警逻辑。
- 识别准确率依赖模型、光照、摄像头角度和 SD 卡中模型文件路径。
- STM32 侧只处理 `FACE:ZENG,score`、`FACE:NONE`、`FACE:ERR,...`。

## 调试日志默认关闭

UART1 是下载和调试接口。为了避免串口占用和运行干扰，模块日志默认关闭。

需要调试时，在对应模块中开启 `*_DEBUG` 宏；测试完成后应恢复为 `0`。

## 传感器数据为 ADC 原始值

烟雾和 PM2.5 当前不再换算为 ppm 或 ug/m3，而是使用 ADC 原始值。

影响：

- 显示、语音和 OneNET 数据更直观，便于根据实际模块调阈值。
- 阈值需要根据实际环境、供电、传感器预热状态重新标定。
- 当前烟雾报警阈值为 `300`，PM2.5 语音报警阈值为 ADC `420`，仅作为当前测试版本默认值。

## CMake 缓存路径问题

如果复制或移动工程后出现 `CMakeCache.txt directory is different`，需要重新生成构建目录缓存：

```powershell
cmake --fresh --preset Debug
```

然后重新构建：

```powershell
cmake --build --preset Debug
```
