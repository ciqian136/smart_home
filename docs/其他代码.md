# 其他代码解析

本文解析仓库根目录中的两个辅助模块代码：`asrpro_code.cpp` 和 `openart.py`。这两个文件不参与 STM32 CMake 编译，但属于项目完整功能的一部分，需要分别部署到 ASRPRO 语音模块和 OpenART 视觉模块。

## 文件定位

| 文件 | 运行位置 | 主要作用 | 与 STM32 的通信口 |
| --- | --- | --- | --- |
| `asrpro_code.cpp` | ASRPRO / 天问 Block 环境 | 语音识别、语音播报队列、向 STM32 发送控制命令 | ASRPRO Serial1 GPIO2/GPIO3，STM32 USART3，9600bps |
| `openart.py` | OpenART 视觉模块 SD 卡脚本 | 加载人脸识别模型，识别 `zeng`，向 STM32 输出识别结果 | OpenART UART2，STM32 UART5，115200bps |

## ASRPRO 代码解析

`asrpro_code.cpp` 负责两类事情：一是把本地语音识别结果转换成 STM32 能解析的文本命令，二是接收 STM32 发来的 `PLAY` / `PLAYS` 播报指令并顺序播放语音片段。

### 核心配置

| 配置 | 当前值 | 作用 |
| --- | --- | --- |
| `RX_BUF_SIZE` | `256` | Serial1 接收行缓冲区大小。 |
| `PLAY_QUEUE_DEPTH` | `64` | 语音播报队列深度，防止连续播报时丢指令。 |
| `PLAY_CMD_ID_MIN` / `PLAY_CMD_ID_MAX` | `1~130` | 允许播放的天问命令词 ID 范围。 |
| `PLAY_VOICE_ID_MIN` / `PLAY_VOICE_ID_MAX` | `10000~65535` | 允许播放的语音资源 ID 范围。 |
| `PLAY_START_RETRY_LOOPS` | `500` | 播放启动失败时最多重试次数。 |
| `PLAY_DONE_WAIT_LOOPS` | `2500` | 等待单条语音播放结束的最大循环次数。 |
| `ASR_WAKE_TIMEOUT_MS` | `30000` | 唤醒词触发后的命令等待窗口。 |
| `ASR_QUERY_WAKE_TIMEOUT_MS` | `30000` | 查询类命令后的等待窗口，避免播报被退出提示打断。 |
| `ASR_SERIAL1_RX_LOG_ENABLED` | `0` | Serial1 接收调试日志开关，默认关闭。 |
| `ASR_BOARD_LED_PIN` | `4` | ASRPRO 板载 LED 测试脚。 |

### 主要数据结构

| 变量 | 作用 |
| --- | --- |
| `snid` | 天问语音识别事件 ID，由 ASRPRO 框架赋值。 |
| `rx_buf` | 接收 STM32 播报指令的文本缓冲区。 |
| `play_queue` | FreeRTOS 队列，用于缓存待播放的语音 ID。 |
| `plays_batch_receiving` | 标记当前是否正在解析一条 `PLAYS` 批量播报命令。 |
| `play_task_busy` | 标记 ASRPRO 播放任务是否忙，用于向 STM32 回传 `VOICE:BUSY` / `VOICE:IDLE`。 |
| `board_led_on` | ASRPRO 本地板载 LED 逻辑状态。 |

### 启动流程

1. `hardware_init()` 创建语音播放队列。
2. 配置 Serial1：GPIO2 为 TX、GPIO3 为 RX，波特率 `9600`。
3. 初始化 ASRPRO 板载 LED，并默认关闭。
4. 设置音量 `vol_set(3)`。
5. 创建两个 FreeRTOS 任务：`app_uart` 负责接收 STM32 指令，`app_play` 负责播放队列。
6. `setup()` 中主要保留语音词条注释和启动期 LED 初始化。

### STM32 -> ASRPRO 播报路径

STM32 通过 USART3 向 ASRPRO 发送文本行：

```text
PLAY:<id>\r\n
PLAYS:<id>,<id>,...\r\n
```

处理流程：

1. `app_uart()` 持续读取 Serial1 字节。
2. 遇到 `\n` 后形成一行，自动去掉末尾 `\r`。
3. `handle_received_line()` 判断是 `PLAY:` 还是 `PLAYS:`。
4. `queue_play_id()` 或 `queue_play_list()` 把合法 ID 写入 `play_queue`。
5. `app_play()` 从队列取 ID，先通过 `VOICE:BUSY` 通知 STM32 当前正在播报。
6. `play_prompt_id()` 调用 `prompt_play_by_cmd_id()` 或 `prompt_play_by_voice_id()` 播放。
7. 队列清空且批量接收结束后，通过 `VOICE:IDLE` 通知 STM32 播放空闲。

### ASRPRO -> STM32 命令路径

语音识别成功后，ASRPRO 框架调用 `ASR_CODE()`，代码根据 `snid` 输出对应控制命令到 STM32。

| `snid` | ASR 语音含义 | 发给 STM32 的命令 |
| --- | --- | --- |
| `0` | 唤醒词“天问五幺” | 不发控制命令，只进入 30 秒等待窗口 |
| `1` | 打开灯光 | `LIGHT:ON` |
| `2` | 关闭灯光 | `LIGHT:OFF` |
| `6~10` | 灯带 1 颜色切换 | `LIGHT:COLOR:WARM/WHITE/RED/GREEN/BLUE` |
| `11~13` | 灯带 1 模式切换 | `LIGHT:MODE:READ/SLEEP/NIGHT` |
| `14` | 打开风扇 | `FAN:ON` |
| `15` | 关闭风扇 | `FAN:OFF` |
| `16~17` | 风速加大 / 减小 | `FAN:SPEED:UP/DOWN` |
| `18~21` | 风扇 1~4 档 | `FAN:SPEED:1/2/3/4` |
| `22` | 打开指示灯 | `LED:ON` |
| `23` | 关闭指示灯 | `LED:OFF` |
| `40` | 切换指示灯 | `LED:TOGGLE` |
| `24` | 当前温度 | `QUERY:TEMP` |
| `25` | 当前湿度 | `QUERY:HUMI` |
| `26` | 粉尘浓度 | `QUERY:DUST` |
| `27` | 光照强度 | `QUERY:LIGHT` |
| `28` | 全部环境信息 | `QUERY:ALL` |
| `39` | 烟雾浓度 | `QUERY:SMOKE` |
| `29~35` | 灯带 2 开关 / 颜色切换 | `LIGHT2:ON/OFF/COLOR:*` |
| `36~38` | 灯带 2 模式切换 | `LIGHT2:MODE:READ/SLEEP/NIGHT` |

### 等待窗口逻辑

当前代码只在两类情况下主动进入 ASRPRO 等待窗口：

- `snid == 0`：唤醒词触发，调用 `set_state_enter_wakeup(30000)`。
- 查询类命令：`24/25/26/27/28/39`，调用 `set_state_enter_wakeup(30000)`。

灯光、风扇、LED 等控制命令执行后不主动打开等待窗口，目的是避免控制一次后马上播报“我退下了”。STM32 发来的外部 `PLAY` / `PLAYS` 播报也不主动打开等待窗口，避免人脸识别或报警播报导致无人唤醒时周期性退出提示。

### 语音片段库

`setup()` 中通过注释形式保留了天问 Block 词条定义。STM32 侧 `APP/voice.c` 会按这些 ID 组合播报内容。

| ID 范围 | 含义 |
| --- | --- |
| `100~110` | 数字零到十。 |
| `111~112` | 百、千。 |
| `113` | 小数点“点”。 |
| `114~115`、`117` | 度、百分之、勒克斯。 |
| `118~121` | 当前温度、当前湿度、当前粉尘数值、当前光照。 |
| `122` | 零下。 |
| `123~124` | 温度偏高、温度正常。 |
| `125` | 当前烟雾数值。 |
| `127~128` | 烟雾数值过高、粉尘数值过高报警。 |
| `129` | 识别到人脸。 |
| `130` | 未识别人员，当前 STM32 逻辑未使用。 |

### ASRPRO 注意事项

- `asrpro_code.cpp` 需要在 ASRPRO / 天问 Block 环境单独烧录，不会随 STM32 固件自动更新。
- 如果语音播报被截断，优先检查 ASRPRO 是否收到完整 `PLAY` / `PLAYS` 行、队列是否足够、是否正确回传 `VOICE:BUSY` / `VOICE:IDLE`。
- `ASR_SERIAL1_RX_LOG_ENABLED` 默认关闭，避免把调试日志混入 STM32 与 ASRPRO 的业务通信。
- 如果环境中的播放 API 名称和参数与当前代码不一致，需要优先按实际天问 Block SDK 调整 `start_prompt_play()`。

## OpenART 代码解析

`openart.py` 运行在 OpenART 视觉模块上，负责加载 TFLite 检测模型、采集摄像头画面、识别目标 `zeng`，并周期性通过 UART2 把识别状态发送给 STM32。

### 核心配置

| 配置 | 当前值 | 作用 |
| --- | --- | --- |
| `UART_PORT` | `2` | OpenART 使用 UART2 与 STM32 通信。 |
| `UART_BAUD` | `115200` | OpenART 与 STM32 UART5 的通信波特率。 |
| `MODEL_PATH` | `/sd/yolo3_iou_smartcar_final_with_post_processing.tflite` | SD 卡中的识别模型路径。 |
| `DETECT_THRESHOLD` | `0.70` | 检测置信度阈值，低于该值不认为识别成功。 |
| `STATUS_INTERVAL_MS` | `300` | 向 STM32 周期输出识别状态的间隔。 |
| `ZENG_LABEL` | `0` | 当前只识别标签 ID 为 `0` 的 `zeng`。 |

### 摄像头配置

代码会尽量让摄像头参数接近训练采集环境：

| 配置 | 当前值 | 说明 |
| --- | --- | --- |
| `CAMERA_BRIGHTNESS` | `-2` | 亮度。 |
| `CAMERA_CONTRAST` | `1` | 对比度。 |
| `CAMERA_SATURATION` | `0` | 饱和度。 |
| `CAMERA_AUTO_EXPOSURE` | `False` | 关闭自动曝光。 |
| `CAMERA_EXPOSURE_US` | `500` | 固定曝光时间。 |
| `CAMERA_AUTO_GAIN` | `False` | 关闭自动增益。 |
| `CAMERA_GAIN_DB` | `0` | 固定增益。 |
| `CAMERA_AUTO_WHITEBAL` | `False` | 关闭自动白平衡。 |

`configure_camera()` 对每个摄像头设置都使用 `try/except`，如果某个 API 在当前固件中不可用，会打印跳过信息并继续运行。

### 启动流程

1. 创建 UART2，波特率 `115200`。
2. 调用 `tf.load(MODEL_PATH)` 加载模型。
3. 如果模型加载失败，每秒发送一次 `FACE:ERR,MODEL`。
4. 初始化摄像头：`RGB565`、`QVGA`。
5. 应用曝光、增益、白平衡等摄像头参数。
6. `sensor.skip_frames(time=2000)` 等待画面稳定。
7. 进入主循环，不断采集图像并执行 `tf.detect()`。

### 识别流程

1. 每帧调用 `sensor.snapshot()` 获取图像。
2. 遍历 `tf.detect(net, img)` 返回的检测框。
3. 只接受 `label == ZENG_LABEL` 且 `score >= DETECT_THRESHOLD` 的目标。
4. 把最高置信度保存为 `best_score`，单位为百分比整数。
5. 将归一化检测框转换为图像坐标，并用 `clamp_rect()` 限制在画面范围内。
6. 在屏幕上绘制红色矩形框和 `zeng` 文本。
7. 每隔 `STATUS_INTERVAL_MS` 向 STM32 发送一次识别状态。

### OpenART -> STM32 通信

识别成功：

```text
FACE:ZENG,<score>\r\n
```

示例：

```text
FACE:ZENG,86\r\n
```

没有识别到目标：

```text
FACE:NONE\r\n
```

模型加载失败：

```text
FACE:ERR,MODEL\r\n
```

STM32 当前只处理 `zeng` 这一个目标，不做多用户身份区分，也不做陌生人识别逻辑。

### 辅助函数

| 函数 | 作用 |
| --- | --- |
| `send_status(text)` | 同时向 UART2 和 OpenART 控制台输出状态文本。 |
| `clamp_rect(x, y, w, h, img_w, img_h)` | 限制检测框坐标不超出图像范围，避免绘制异常。 |
| `configure_camera()` | 设置摄像头亮度、对比度、曝光、增益和白平衡。 |

### OpenART 注意事项

- `MODEL_PATH` 必须和 SD 卡实际文件路径一致，否则会持续输出 `FACE:ERR,MODEL`。
- 当前脚本按 `300ms` 周期输出状态，STM32 侧再通过连续确认降低单帧误判影响。
- 如果摄像头画面过暗、过曝或角度变化大，优先调整摄像头参数和 `DETECT_THRESHOLD`。
- OpenART 只负责输出识别状态，不直接控制语音模块；人脸播报由 STM32 的 `APP/face.c` 和 `APP/voice.c` 联动完成。

## 与 STM32 的关系

| 外部代码 | STM32 对接模块 | STM32 处理逻辑 |
| --- | --- | --- |
| `asrpro_code.cpp` | `APP/voice.c`、`APP/my_uart.c` | UART3 接收 ASRPRO 命令，控制灯带、风扇、LED 和查询播报；向 ASRPRO 发送 `PLAY` / `PLAYS`。 |
| `openart.py` | `APP/face.c`、`APP/voice.c`、`APP/my_uart.c` | UART5 接收 `FACE:*` 状态，确认识别 `zeng` 后请求语音播报。 |

两个辅助模块都通过文本协议和 STM32 解耦。这样 STM32 只需要处理稳定的串口命令，不需要直接关心 ASRPRO 的语音词条实现或 OpenART 的模型推理细节。
